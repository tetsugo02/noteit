## 2026-11-07のCPU Docker確認

Docker Engine 29.6.2／Compose 5.3.1を使用し，Apple Silicon上で`linux/amd64`をエミュレーションして確認しました．検証専用のComposeプロジェクトを使用し，既存コンテナは変更していません．

ビルド時に，TorchCodec 0.10.0のCPU版にLinux ARM64用wheelがないことが判明したため，Composeに`platform: linux/amd64`を明示しました．また，モデル一覧でCTranslate2をimportするとtorchまで初期化され，初回の接続テストがタイムアウトしました．GPU検出と既定モデル選択を，推論ライブラリのimportを伴わない，時間制限付きのドライバー照会へ変更しました．追加した回帰テストを含む44件とRuffは成功しています．

確認済みの項目は次のとおりです．

- 修正後のCPUイメージのビルド・起動，Dockerヘルスチェックの正常化．
- 非rootユーザー（UID 10001）での実行，モデルをダウンロードせずに起動・モデル一覧を取得できること．
- APIトークンなし／不正トークンでの401応答と，正しいトークンでのモデル・CPUデバイス情報取得．
- `tiny`・英語・話者分離OFFの実音声認識，元音声の時間軸，話者ラベルnull，TXT／JSON保存，重複投入時の再利用，完了後のアップロード・デコード用音声の削除．初回の取得・読み込みを含む処理時間は41.9秒でした．
- 話者分離処理中もモデル一覧が応答すること（約0.05秒）．

利用者の指示により，話者分離の処理途中で検証を終了しました．その時点で話者分離のエラーは出ていませんでしたが，完了は未確認です．コンテナ再起動後の結果取得，中断状態・残存音声の起動時整理，Dockerを接続先とするGUI／MCPの往復は今回未確認です．検証ドライバーと検証用コンテナは停止しました．NVIDIA実機でのCUDA検証も引き続き未実施です．

## 2026-11-13のMacアプリ起動確認

Finderから起動した既存の`noteit.app`でSIGABRTが発生しました．既存バイナリを`PATH=/usr/bin:/bin:/usr/sbin:/sbin`で起動し，Tauriのsetup中に`No such file or directory (os error 2)`となることを再現しました．シェルのPATHにはある`uv`をFinderのPATHでは発見できず，Pythonサービスを起動する前に失敗していました．開発起動は成功しています．

PATH上で`uv`が見つからない場合に標準インストール先を探索する処理と，サービス起動エラーをダイアログ表示して終了する処理を追加しました．以下を確認しています．

- Rustの起動処理の回帰テスト3件が成功．PATHにない実行ファイルへのフォールバック，空白を含むパス，`NOTEIT_PYTHON`明示時の失敗，`uv`未発見時の案内を確認．
- React / TypeScript / Viteの本番ビルドと，`tauri build --debug --bundles app`（`bundle.active=true`を指定）による`.app`生成が成功．
- 生成した`.app`を上記の最小限のPATHで起動し，ネイティブ画面の描画，共通サービス接続，モデル・デバイス一覧と既存履歴の表示を確認．共通サービスは開発起動で作成した既存プロセスを再利用しました．

今回の確認範囲は起動・接続であり，音声認識は再実行していません．
